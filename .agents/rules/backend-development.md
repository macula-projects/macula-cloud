# 后端开发规则

修改 Java 后端、REST API、数据模型、服务逻辑或数据库访问时加载。

## 分层与模型

- Controller 负责 HTTP 协议适配、输入校验和 Service 编排，不编写持久化或复杂业务规则，也不吞掉应由统一异常处理返回的异常。
- Service 负责业务规则和事务边界。一次业务操作需要原子性时，在公开 Service 方法上使用 `@Transactional`，并明确回滚语义。
- Mapper 负责数据访问；优先沿用 MyBatis-Plus 与现有 XML Mapper 风格，不在 Java 中拼接 SQL，不让 Mapper 依赖上层类型。
- 沿用仓库模型语义：Query 表示查询条件，Form 表示写入表单，DTO 表示跨层或跨服务传输，VO 表示展示结果，BO 表示组合查询结果，Entity 与数据库表映射。
- 使用现有 Converter/MapStruct 做模型转换；避免在 Controller 中堆叠复制字段的代码。
- Entity 不作为新增 REST 或 Feign 公共契约。公共契约放入对应 `*-api` 模块，并控制第三方类型泄漏。

## REST 与远程 API

- 沿用 `/api/v1/<resources>` 风格：路径使用小写和连字符、资源名优先用复数、路径末尾不加 `/`，用 HTTP 方法表达操作。
- 输入使用 Bean Validation；分页必须有合理边界，禁止把任意 SQL、排序表达式或无限结果集直接暴露给调用方。
- Controller 返回业务对象，由 Macula Boot Web 能力统一包装；不要在同一模块中混用多套响应包装方式。
- 新增或变更 Feign 接口时，同时验证服务端映射、调用方、fallback、序列化模型和鉴权头传递。
- 破坏兼容性的字段、路径或语义变化应新增 API 版本或提供明确迁移过程，不直接覆盖仍有调用方的契约。

## 认证、授权与租户

- IAM 的 OAuth 2.1、安全过滤链、grant、客户端和身份源改动属于高风险变更；默认保持标准流程与已有兼容入口，并补充失败路径测试。
- Gateway 的路由、鉴权、加解密或权限缓存改动应验证允许、拒绝、匿名、过期凭据和下游不可用场景。
- System 的用户、角色、菜单、权限和租户改动应检查缓存刷新、数据权限、超级管理员边界及前端权限指令。
- 不信任来自请求参数的租户、角色或用户身份；以通过校验的安全上下文为准。
- 禁止在日志、异常消息、测试数据或配置文件中暴露密码、secret、token、验证码和完整敏感个人信息。

## 配置与持久化

- `bootstrap.yml` 只保留应用标识、profile 激活和配置中心引导信息；业务配置放在 `application.yml` 或配置中心。
- 新增配置支持环境变量或配置中心覆盖，并提供适合本地开发的安全默认值；不硬编码生产地址与凭据。
- 数据库字段、索引或初始化数据变化时，同步维护模块 `docs/*.sql` 或既有迁移材料，并说明升级与回滚影响。
- 修改 Mapper XML 时核对参数名、result map、分页、空集合和数据库方言；不要用字符串替换构造动态 SQL。

## 代码与文档

- 新增 Java 文件复制相邻文件的 Apache License 2.0 版权头。
- 新增或实质修改的类、接口、枚举、注解、Record 及测试类应有职责清晰的类级 Javadoc；顶层类型包含非空 `@author`、`@since`。
- 公共 API 按需说明参数、返回值、异常和安全约束；注释解释意图与约束，不逐行翻译实现。
- 行为、配置键、API、部署前提或扩展点变化时更新目标模块 README；不要依赖过时官网内容代替仓库文档。
