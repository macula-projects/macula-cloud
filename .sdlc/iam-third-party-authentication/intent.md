# Intent: IAM 企业微信与 GitHub 第三方身份认证
Author: Rain. Status: accepted.

## Problem
Macula Cloud IAM 当前不支持企业微信和 GitHub 作为登录身份源。需要使用这两类身份的用户只能改用现有认证方式，企业内部身份和开发者常用身份无法直接用于平台登录，增加了登录与账号管理成本。

## Proposed outcome
用户能够从 IAM 登录流程选择企业微信或 GitHub，完成第三方认证并得到明确的成功或失败结果；两种认证方式可使用数据库中维护的配置，并且不破坏短信认证等现有登录方式。新增身份源应形成可继续扩展其他第三方认证方式的清晰边界。

## Affected users and systems
- 使用企业微信的组织成员和使用 GitHub 身份的用户。
- IAM 登录、认证结果处理和账号识别流程。
- 保存企业微信与 GitHub 身份源配置的数据库数据及其管理方。
- 现有短信认证及其他登录方式，需要保持兼容。

## Constraints
- 参考现有 authentication 短信认证模式，保持现有认证流程兼容。
- 企业微信和 GitHub 配置必须从数据库读取，不以静态配置替代。
- 每种认证方式在 authentication 下使用独立子包，并为未来扩展其他身份源保留适当扩展空间。
- 必须保持租户、账号和权限边界清晰，不允许第三方身份跨租户误关联。
- 当前阶段只确认需求意图，不预先指定具体框架、表结构或实现方案。

## Open questions
- 第三方认证成功后应仅匹配已有账号、支持用户绑定，还是允许自动创建账号？
- 企业微信和 GitHub 分别面向哪些用户与租户，身份源配置是平台级、租户级还是两者兼有？
- 本期是否包含登录页入口、授权回调、账号绑定与解绑、失败提示，以及两种认证方式的独立启停？
- 当第三方返回的身份无法匹配账号、账号被禁用或所属租户不一致时，期望的用户体验和运营处理方式是什么？
- 是否存在上线期限、历史调用兼容要求或明确排除的范围？
