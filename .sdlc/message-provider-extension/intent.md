# Intent: 邮件服务扩展、自定义短信与消息包结构整理
Author: Rain. Status: accepted.

## Problem
平台消息设置目前缺少 Exchange、163 免费邮箱和个人 QQ 邮箱的独立配置入口；短信仅支持阿里云与腾讯云，无法通过配置接入自有短信发送服务。IAM 邮件、短信接口与具体实现混在同一包，扩展职责不够清晰。

## Proposed outcome
平台管理员可配置并使用企业自建 Exchange、163 免费邮箱、QQ 邮箱发送邮件，保留现有自定义 SMTP 和企业邮箱选项；可通过配置 POST URL 和认证 Header 接入自定义短信发送服务，模板配置沿用现有方式。新增渠道同时覆盖管理端测试发送与 IAM 登录验证码发送。邮件与短信的抽象接口位于对应职责包，具体实现位于 impl 或职责明确的子包，调用方依赖接口。

## Affected users and systems
平台消息设置管理员、接收邮件与短信的用户，以及 Macula Cloud Admin、System、IAM 的消息配置、模板和发送链路。

## Constraints
本轮聚焦邮箱类型扩展、自定义短信和邮件短信相关包结构；不扩大至其他 IAM 包结构整理。Exchange 范围为企业自建，本轮不包含 Microsoft 365；自定义短信使用 POST URL 和认证 Header，沿用现有模板配置，不新增短信正文模式。保留已有供应商、渠道启停、模板及凭据保护行为。配置和实际发送行为保持一致。遵循 Java 17 及当前平台技术基线，同步更新相关文档与测试。不提交、推送、部署，不修改业务数据库，不使用真实收件人发送测试消息。未获人工批准的 intent、spec、plan 不得作为实施依据。

## Open questions
- 企业自建 Exchange 的实际 SMTP 认证方式及服务端要求，需在设计阶段明确。
- 自定义短信 POST 请求体字段与响应成功判定契约，需在设计阶段明确。
