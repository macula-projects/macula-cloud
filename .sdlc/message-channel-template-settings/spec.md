# Spec: 邮件和短信发送渠道与模板配置优化 (from intent.md 2026-10-16)
Status: accepted

## Source intent
[已接受的 intent.md](./intent.md)：提供平台全局的邮件模板、邮件服务和短信服务配置，并将有效配置接入真实业务发送链路。

设计约束来源：仓库 `AGENTS.md`，`.agents/rules/architecture.md`、`backend-development.md`、`frontend-development.md`、`testing.md`，根目录 `REVIEW.md` 与 `bands.yaml`，以及 `macula-cloud-system/README.md`、`macula-cloud-iam/README.md` 和目标模块现有实现/测试。未发现另行提供的品牌或法规政策。

## Requirements
1. 管理端“消息设置”必须按任务截图提供“邮件模板”“邮件服务”“短信服务”三个页签；加载、空数据、失败、保存中和重复提交状态必须有明确反馈。
2. 邮件模板必须且只包含绑定邮箱、修改绑定邮箱、忘记密码、修改密码、管理员重置密码成功、登录验证、密码到期提醒、欢迎邮件八个场景；每个场景支持浏览预览和配置。
3. 每个邮件场景必须提供“自定义邮件”开关。关闭时使用代码内置的安全默认模板；开启时保存并使用发件人显示、主题和 HTML 内容，且只能使用该场景声明的变量。
4. 邮件模板预览必须使用示例变量渲染当前有效模板，不发送邮件；预览不得执行脚本、提交表单、访问父页面或泄露凭据。
5. 邮件服务是平台全局单选配置，支持总开关及自定义 SMTP、阿里云企业邮、腾讯云企业邮、网易企业邮四种提供商，不展示 Exchange 独立类型。自定义 SMTP 配置服务器、端口、用户名、密码以及 None/SSL 安全模式；三种企业邮配置发件人邮箱和密码，并使用服务端维护的 SMTP 预设。
6. 短信服务是平台全局单选配置，支持总开关及阿里云、腾讯云两种提供商，不展示或接受七牛云、自定义短信及其他提供商。
7. 阿里云短信配置 AccessKey ID、AccessKey Secret 和短信签名；腾讯云短信配置地域、SecretId、SecretKey、短信应用 ID 和短信签名。服务端必须按提供商白名单校验字段，不接受未知字段或把敏感值放进普通 JSON 配置。
8. 短信场景必须且只包含绑定手机号、绑定手机号成功、修改手机号、忘记密码、修改密码、管理员重置密码成功、登录验证、欢迎短信、密码到期提醒九个场景；每个提供商及语言保存对应模板 ID/CODE。界面提供截图中的中文和 English 切换，语言代码固定为 `zh-CN` 与 `en-US`。
9. 每个短信场景必须提供测试发送。管理员临时输入手机号和所需变量；服务端只使用已启用的当前全局提供商和已配置的模板编码发起真实供应商请求，限制重复发送并返回“已提交”或经过清洗的失败原因，不能把最终送达等同于供应商受理。
10. 邮件和短信服务关闭时，真实业务发送必须拒绝该渠道的投递并返回可识别的“渠道未启用”结果，不能静默伪装成功；开启时必须使用当前有效提供商、场景模板和语言投递。
11. 消息发送必须提供稳定的窄化业务契约。调用方只能提交场景、目标地址或手机号、语言和声明过的变量，不能指定数据库 ID、任意供应商、任意模板正文或任意远程端点。IAM 按已确认的部署约束直接读取与 System 共用数据库中的平台消息配置，不通过 IAM→System 远程调用。
12. IAM 中现有短信登录必须停止使用“任意验证码均通过”的占位实现：验证码请求生成不可预测的一次性验证码，经 System 的登录验证场景发送；验证码仅以不可逆摘要存入 Redis，带有效期、发送频率、失败次数和一次性消费控制；验证失败不得建立认证。
13. 已存在且具备对应触发点的绑定、密码、欢迎和到期提醒流程必须通过同一跨服务契约投递。仓库中不存在的业务触发流程如何处理，见 Flagged concerns，不得以测试发送代替真实业务接入。
14. 管理 API 沿用现有网关 URL 权限，不新增独立权限。管理页面和管理 API 需要已认证且被现有消息设置菜单/URL 权限授权；运行时发送 API 必须只允许受信服务身份调用，不能被浏览器用户或匿名请求直接调用。
15. 密码、AccessKey Secret、SecretKey 等凭据必须写入专用加密字段，任何读取响应、日志、审计、异常和前端状态都不得包含明文；响应只返回 `credentialConfigured` 一类布尔状态。加密失败必须阻止写库并回滚。
16. 平台全局配置不得依赖请求租户，也不得接受 `tenantId`。发送审计只记录调用服务、场景、提供商标识、结果和不可逆目标摘要，不记录完整邮箱、手机号、验证码、模板变量或凭据。
17. 不迁移或兼容历史消息配置数据；但不得修改已发布的 Flyway 迁移文件。实现可复用现有表结构并忽略/拒绝范围外旧行，必要的结构变化必须新增迁移。
18. 中文和英文界面文本进入现有国际化资源；页面沿用 Vue 3、Element Plus、现有请求封装和动态菜单，不新增前端框架。

## Non-goals
- 不支持七牛云短信、自定义短信、Exchange 独立邮件类型或任务截图之外的服务商。
- 不提供租户级覆盖、多套提供商并行、自动故障转移或发送队列管理后台。
- 不把供应商受理状态表述为最终送达，不建设供应商回执、退信处理或营销群发能力。
- 不迁移、清洗或兼容已有消息配置数据，也不修改已经执行的 Flyway 迁移历史。
- 不新增消息设置权限模型；仍由现有菜单和 URL 权限控制管理入口。
- 不在 Macula Cloud 中复制通用加密框架；`@CryptoField` 的失败关闭语义应由 Macula Boot 提供或修复。

## Design
消息配置管理和管理员测试发送由 `macula-cloud-system` 负责。根据产品负责人确认的部署约束，IAM 与 System 共用数据库，短信登录由 IAM 直接读取消息配置并调用当前短信供应商，不新增 IAM→System 远程调用。IAM 只按固定登录场景读取当前启用的 SMS 配置和模板，不提供通用配置管理入口；这一共享数据库例外及其耦合风险保留在 Flagged concerns 中。

管理页面改为三个页签。邮件模板页按固定场景展示说明、“配置”和“浏览”；编辑抽屉使用场景变量白名单，关闭自定义时只保存关闭状态并展示默认模板预览。邮件服务和短信服务页各只有一个总开关与一个提供商选择，切换提供商后显示固定字段；短信场景表把模板编码按 `zh-CN`/`en-US` 分开维护，并从行内发起测试。

System 服务新增统一的运行时调度入口。调度器按渠道读取唯一平台配置，校验启用状态，按场景和语言选择覆盖模板或默认模板，严格校验变量集合，渲染后调用固定提供商适配器。适配器只接收经过类型化校验的配置，不接受由请求传入的 URL。邮件企业邮端点和端口使用代码内白名单预设；自定义 SMTP 只允许合法主机名或 IP、1–65535 端口和显式安全模式，并设置连接、读写超时。短信只调用阿里云和腾讯云官方 SDK。

邮件 HTML 先用场景变量的 HTML 转义值渲染，再通过允许列表清洗；预览在带 `sandbox` 且禁止脚本、表单和顶层导航的 iframe 中显示。短信保持纯文本并按供应商要求转换变量顺序。模板变量缺失、多余或无法渲染时拒绝保存/发送。

IAM 验证码服务负责生成、摘要存储、频率限制、一次性校验，以及依据共享数据库配置完成登录短信投递。Redis 键使用独立命名空间并基于标准化手机号摘要分区；发送成功后才发布可校验记录，失败不留下可用验证码。验证码和原始手机号不写日志。IAM 不调用 System 服务，也不开放匿名内部发送端点。

供应商配置更新在事务内完成并保证每个渠道最多一个当前配置。切换服务商时，新配置通过字段校验后原子替换有效配置；关闭渠道不删除配置。删除式 CRUD 不再暴露给新页面。编辑已保存配置时，敏感字段留空表示保持原值；读取接口始终不回显明文。加密失败必须阻止写库并回滚。

## Data and interfaces
复用 `sys_message_provider` 和 `sys_message_template`，不修改已执行的 `V2__admin_identity_security_settings.sql`。`sys_message_provider` 每个渠道只使用一个有效配置：`channel` 为 `MAIL|SMS`，`provider_type` 为邮件 `CUSTOM|ALIYUN|TENCENT|NETEASE` 或短信 `ALIYUN|TENCENT`；`credential` 保存加密秘密，`config_json` 只保存非敏感的端口、安全模式、地域或短信应用 ID。`sys_message_template` 使用固定场景 key、`zh-CN|en-US`、提供商 code 和模板编码；邮件默认模板和关闭自定义后的内容来自代码常量。

管理 API 目标契约：
- `GET /api/v1/message-settings/providers/{channel}`：读取当前全局渠道配置，只返回非敏感字段和凭据已配置标记。
- `PUT /api/v1/message-settings/providers/{channel}`：校验并原子保存渠道启用状态、提供商及其固定字段。
- `GET /api/v1/message-settings/templates/{channel}?providerType=&languageCode=`：返回该渠道固定完整场景及有效配置。
- `PUT /api/v1/message-settings/templates/{channel}/{scene}`：保存一个场景配置；拒绝未知场景、提供商、语言、变量和过长内容。
- `POST /api/v1/message-settings/templates/MAIL/{scene}/preview`：返回经过清洗的邮件预览 HTML。
- `POST /api/v1/message-settings/test`：仅供现有管理权限调用，使用当前全局配置测试单个固定场景。

运行时契约目标：System 管理端测试发送和 IAM 短信登录都只接受 `scene`、`target`、`languageCode`、`variables` 和幂等键，由 scene 推导渠道，并区分 `SUBMITTED`、`CHANNEL_DISABLED`、`CONFIG_INVALID`、`PROVIDER_REJECTED`。IAM 使用独立的只读 Mapper 访问共享的 `sys_message_provider`、`sys_message_template` 表，不依赖 System 的 Entity、Mapper、Service 或资源文件；读取和供应商调用失败必须失败关闭并只保留可诊断的非敏感错误。

IAM 新增验证码请求端点时须具备 CSRF/同源保护、手机号格式校验、按 IP 与手机号摘要双维度限流以及统一响应，避免枚举账号；验证码 Redis 记录只保存摘要、到期时间、失败计数和使用状态。

## Flagged concerns
- `@CryptoField` 当前文档说明加密失败可能继续写库，与“凭据不得明文落库”冲突；产品负责人已确认失败必须阻止写库，因此实施前必须用自动化测试证明失败关闭，若当前 Macula Boot 不能满足则停止凭据写入并先修复上游能力，blocking。
- IAM 直接读取 System 数据库是产品负责人明确选择的部署约束，但它例外于仓库“跨服务通过 API/Feign、不得引用其他服务实现”的默认架构规则；实现必须只共享表契约、不引用 System Java 实现，并验证 IAM 与 System 数据源确实指向同一 schema，non-blocking。
- 敏感字段更新语义已由产品负责人确定为“留空保持原值”；必须覆盖新增时必填、编辑留空保留、读取不回显和替换凭据四条路径，non-blocking。
- 产品负责人选择本次仅接入仓库已有的短信登录触发点；绑定邮箱/手机号、找回密码、欢迎通知和到期提醒等尚不存在的端到端流程不在本次新增，后续流程按同一固定场景和配置表契约接入，non-blocking。
- 现有另一变更已加入 Exchange、自定义短信、通用测试场景和多提供商 CRUD，与本 intent 的截图范围不同：本任务会从新页面和新契约移除/拒绝这些范围外能力，且不兼容其历史配置；这符合已接受的“不迁移和兼容”，但可能影响尚未发布的并行变更，non-blocking。
- 短信供应商模板参数顺序和双语模板必须在供应商控制台预先审核，仓库测试只能证明请求构造和受理处理，无法证明真实终端最终送达；上线验收需要隔离的供应商测试账号与审核模板，non-blocking。
- `bands.yaml` 仅定义公共 API 延迟、错误率和无关的 checkout 转化率，未定义消息投递成功率或供应商延迟控制带；首版沿用公共 API 监控并记录结构化提交结果，专用消息 SLO 留待运维提供基线，non-blocking。

## Verification strategy
后端单元测试覆盖固定场景全集、提供商白名单、全局单配置、启停行为、默认/自定义模板选择、双语模板编码、变量缺失与注入拒绝、凭据不回显、空凭据的最终选定语义、加密失败回滚、邮件 HTML 清洗、短信/邮件供应商请求构造、超时与供应商拒绝、测试限流和审计脱敏。

Controller/Security 测试覆盖管理 API 的允许与拒绝，匿名和未授权浏览器令牌均被拒绝。IAM 数据访问测试覆盖固定登录场景的只读查询、关闭/无效配置失败关闭、凭据解密失败、阿里云/腾讯云请求构造和共享 schema 前提；验证码测试覆盖随机性、摘要存储、TTL、发送失败不生效、错误次数、过期、重放、并发消费、IP/手机号限流以及错误验证码不能认证。

数据库集成测试在隔离的 `macula_settings_it_*` 数据库验证凭据密文落库、读取不回显、每渠道唯一有效配置及事务回滚；不修改已执行迁移。真实供应商联调使用专用测试账号，不在自动化测试或日志中保存真实密钥和个人手机号。

前端 Vitest/Cypress 覆盖三个页签、八个邮件场景、九个短信场景、四种邮件和两种短信提供商字段、中文/English 切换、启停、编辑与凭据占位语义、邮件浏览 sandbox、短信测试发送、loading/空态/错误态/重复提交，以及七牛云、自定义短信和 Exchange 不出现。

实现完成后依次运行 System/API 目标测试、IAM 目标测试、管理端单元测试与构建，再运行消息设置关键 Cypress 流程；具备隔离 MySQL/Redis 和供应商测试账号时补充集成与真实受理验证，未具备的环境必须在验证报告中明确列出。
