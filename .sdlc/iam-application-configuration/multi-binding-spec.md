# Spec: 身份源多条首次自动绑定映射
Status: accepted
Author: Rain

## Source intent
沿用已接受的[intent.md](intent.md)身份源配置范围；Rain补充“身份绑定是可以多个的，比如手机对手机、邮箱对邮箱”。本增量待审阅，不改变原spec/plan已接受部分的状态。

## Requirements
1. 同一身份源可同时保存多条源字段到IAM用户字段映射，例如MOBILE→MOBILE、EMAIL→EMAIL；界面支持增删行及完整回显。
2. 每条映射都必须在当前来源已启用能力共同支持的可信字段白名单内；拒绝重复映射、未知字段、空规则及自动绑定开启但规则为空。
3. 已有有效绑定优先。仅首次未绑定身份执行所有可用规则，单条无属性或无匹配不贡献候选；至少一条匹配，且所有匹配归于同一IAM用户时才自动绑定。
4. 任一规则匹配多个账号，或不同规则匹配不同账号，均停止自动绑定，转现有账号证明页面；不按顺序任选，也不自动合并账号。
5. 属性只取服务端核验的厂商身份或受控目录结果，保持手机号证明的专用限制；不新增敏感字段授权。
6. 保持registration、Client、租户、用户类型及组织准入边界，绑定事务内重查完整规则及候选；配置变更使旧证明失效。

## Non-goals
不回写IAM用户资料，不改变已有绑定，不合并账号，不扩展企微敏感信息授权，不增加厂商登录接口。

## Design
共享映射元素沿用现有源/目标字段枚举。System负责规则集合校验与原子保存；IAM初次解析和绑定事务重查调用同一集合匹配逻辑；Admin展示多行映射。不增加Gateway授权入口。

## Data and interfaces
新增bindingMappings数组，每项含sourceField和targetField；追加数据库迁移保存集合。旧单条配置等价读为一项，不新增规则或改写已有用户绑定。历史请求省略新字段时保留集合；旧单条写请求仅在能无损表示当前配置时兼容，多条配置遇到旧写入应明确拒绝，避免静默截断。显式空集合只允许关闭自动绑定。更新继续使用现有version CAS与提交后缓存失效。

## Flagged concerns
- 多条匹配采用“任一命中且所有命中一致”，并非要求手机号邮箱都存在或都匹配；冲突和歧义转账号证明。此语义需要Rain确认：[blocking]。
- 仓库AGENTS.md要求“No source code is written for a change without an accepted plan.md”；本次改变可信身份绑定行为，须先接受增量规格并形成经审阅的增量计划：[blocking]。
- 适用策略为AGENTS.md及architecture、backend-development、frontend-development、testing规则；未发现额外组织级策略技能。真实厂商可用属性仍受其授权限制，多条配置不代表每次都有全部字段：[non-blocking]。

## Verification strategy
覆盖单规则历史兼容、多规则回显与增删、请求无损兼容、任一字段缺失、无命中、同用户多命中、不同用户冲突、单规则多账号、非法字段、能力收缩、已有绑定优先和锁内配置变更；隔离数据库验证升级与并发绑定，随后执行相关及全量后端、前端单测/构建和关键流程浏览器回归。Mock通过不替代真实厂商联调。


2026-11-10 接受记录：Rain在回调增量方案展示后回复“YES，再加上 身份绑定是可以多个的”，明确接受本回调与多条绑定增量。多条绑定采用任一命中且所有命中一致，冲突转账号证明。此确认接受规格，不自批尚未展示的实施计划。原blocking规格决策已解决；计划接受门仍待后续人工确认。
