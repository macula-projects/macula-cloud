# Intent: IAM 外部凭证登录
Author: Rain. Status: accepted.

## Problem
业务系统可以从飞书、钉钉、企业微信、微信及号码认证服务取得第三方签发的短期 code 或 Token，但 IAM 尚未提供统一入口核验这些凭证、取得可信第三方身份并颁发 Macula access token。调用方只能重复实现第三方换码和本地账号定位，容易造成不同入口身份不一致、凭证处理不安全或绕开既有 OAuth Client、租户与用户权限边界。

## Proposed outcome
任何获准的调用方在取得第三方短期凭证后，都可以把凭证提交给 IAM。IAM 向对应第三方服务核验凭证、取得可信身份、在 OAuth Client 指定的业务范围内定位已启用的业务员账号，并颁发现有 Macula access token 和适用的 refresh token。同一业务员通过浏览器、端内网页、小程序或其他客户端取得凭证时，应落到同一 Macula 账号；未绑定身份进入与 GitHub、企业微信一致的账号绑定流程，无效、重放、不唯一或越权的凭证必须被明确拒绝。

## Affected users and systems
受影响用户为业务员。受影响系统包括 Macula Cloud IAM、System 中的用户和身份源配置、OAuth Client 配置、现有第三方身份绑定，以及飞书、钉钉、企业微信、微信和阿里云号码认证服务。取得 code 或 Token 的 App、网页、小程序及其 SDK 集成不属于本变更范围。

## Constraints
- IAM 只负责接收和服务端核验第三方已经签发的短期凭证，不负责集成、加载或管理任何客户端 SDK、JSSDK、原生 App、业务网页或小程序代码。
- 第三方 code、阿里云号码认证 Token 等凭证必须由 IAM 服务端向对应平台核验；请求声明的用户标识、手机号、租户、组织、应用或账号信息不能直接作为认证依据。
- 飞书继续以可信换码结果中的 `employee_no`、钉钉继续以目标组织成员 `userId` 定位第三方身份；微信普通登录和微信小程序登录统一使用可信换码结果中的 `unionid`，缺少 `unionid` 时不得降级使用 `openid` 登录。
- 微信小程序登录 code 和手机号 code 是两种相互独立的凭证：登录 code 按 `unionid` 解析微信身份；手机号 code 按服务端取得的手机号定位账号，匹配不到账号时进入手机号绑定流程，不自动注册用户。
- 未绑定的飞书、钉钉、企业微信和微信身份必须复用现有 GitHub、企业微信的账号绑定闭环，不得静默注册、静默绑定或仅因第三方资料相似而关联账号。
- 阿里云号码认证结果只能使用服务端取回的手机号；手机号缺失、重复、跨越 OAuth Client 指定范围或账号不可用时不得直接登录，匹配不到账号时进入手机号绑定流程。
- 每个 OAuth Client 必须显式配置允许使用的第三方凭证类型；未配置时拒绝全部第三方凭证，只保留 `SysUser` 中已有的用户名、手机号和邮箱本地身份入口。用户名、手机号和邮箱都可以作为标识配合密码登录；手机号还可以使用短信验证码，邮箱还可以使用邮件验证码。任一字段未填写、无法唯一定位或账号不可用时不得登录。
- 登录必须受 OAuth Client 配置的租户、用户类型、scope 和 Token 策略约束，不得因为第三方认证成功而扩大授权。
- 第三方凭证必须短期、一次性使用或具备等价的防重放控制；code、Token、手机号、第三方主体、供应商原始响应及异常消息不得进入日志或长期持久化。
- 本变更只颁发协议层 Token，不建立或依赖浏览器 Session，也不改变现有 `/oauth2/authorize`、网页登录、密码和短信验证码登录闭环。
- 登录只验证身份、定位现有业务员账号或进入明确的绑定流程，不自动注册、自动建档、自动跨租户匹配或静默绑定第三方身份。
