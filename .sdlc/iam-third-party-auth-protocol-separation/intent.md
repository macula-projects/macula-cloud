# Intent: IAM 第三方身份认证与协议解耦及企业微信双场景登录
Author: Rain. Status: accepted.

## Problem
当前 GitHub、企业微信身份认证要求存在有效的 IAM OAuth2 client，并在第三方回调时再次校验该 client。没有这种 client 上下文时，用户无法发起或完成第三方身份认证；身份核验被错误地绑定到 IAM 对外提供的某一种认证协议。当前还在身份认证阶段解析本地账号、租户和用户类型：GitHub 要求事先存在绑定，企业微信直接把 UserId 当成本地 username；缺少让未匹配用户完成安全绑定的环节。企业微信当前只接入了内置 WebView 的网页授权，用户在系统浏览器中无法使用企业微信新版网页登录扫码或桌面端快速登录。

## Proposed outcome
GitHub 和企业微信身份能够独立完成外部身份核验，不以 OAuth2 client 是否存在作为前提。核验后再进行本地账号关联：企业微信成员优先用 UserId 匹配有效的本地 username，匹配不到时进入绑定；GitHub 等社交身份已有绑定时直接登录，未绑定时进入绑定界面。用户可通过传统密码、短信或已登录会话证明本地账号归属，不在此流程注册账号。只有完成账号关联并校验本地账号后才授予本地登录权限。由进入 IAM 的具体认证协议分别负责自身的 client 校验；登录成功后沿用原有服务端 redirect，直接打开 IAM 登录页也能完成登录。使用企业微信的用户在系统浏览器和企业微信内置 WebView 中，都能通过各自适用的官方流程完成身份核验，并得到明确的成功或失败结果。

## Affected users and systems
- 使用 GitHub 或企业微信身份登录的用户，尤其是系统浏览器中的企业微信用户，以及非 OAuth2 client 场景下进入 IAM 的用户。
- IAM 第三方身份认证、登录页面、认证结果与本次新增的账号绑定环节，以及不同认证协议进入 IAM 后的续转。
- 可能参与本地账号绑定的用户体系及账号管理方。
- 企业微信自建应用的网页登录配置、回调域名与相应运维配置方。
- 现有密码、短信、小程序及 OAuth2/OIDC 等登录或授权流程，需要保持行为兼容。

## Constraints
- 第三方身份认证与 IAM 提供的对外认证协议分层；不以 OAuth2 client 校验替代身份核验，也不让第三方身份认证承担各协议自己的 client 校验。外部身份核验阶段不处理本地账号绑定、租户、用户类型或权限授予；这些由后续账号关联环节处理。
- 企业微信系统浏览器网页登录按[官方新版文档](https://developer.work.weixin.qq.com/document/path/98152#2-%E6%9E%84%E9%80%A0%E4%BC%81%E4%B8%9A%E5%BE%AE%E4%BF%A1%E7%99%BB%E5%BD%95%E9%93%BE%E6%8E%A5)自行构造登录链接，不使用其 JS 登录组件；企业微信内置 WebView 保留适用的网页授权场景。
- 优先根据运行环境自动选择企业微信登录方式；企业微信桌面客户端内置页面按 WebView 场景考虑。若不能可靠识别，则提供两个明确的登录地址供用户选择。现有 `/login/wecom` 入口和已登记回调地址保持兼容。
- 企业微信成员仅在 UserId 能唯一匹配有效本地 username 时直接关联；匹配不到时转入绑定。GitHub 等社交身份不依赖 username 自动匹配；已有绑定直接登录，未绑定才进入绑定界面。
- 新绑定只接受传统密码、短信或已登录会话证明目标本地账号归属；不能仅凭用户填写 username 获得账号权限，不允许在此流程注册新账号。
- 登录成功后的 redirect 保持现有服务端受控规则；没有待续转协议的直接登录也应有可用的默认落点，不接受第三方或浏览器提供的任意外部跳转。
- 第三方回调必须保持防伪、一次性和失败关闭；不得因去除 OAuth2 client 依赖而放松后续绑定、租户、账号、权限或回跳地址边界。
- 第三方配置继续从现有受控身份源配置读取，不能从浏览器请求接受密钥或任意第三方端点。

## Open questions
无；绑定凭据、未绑定行为和直接登录范围已由需求方确认。具体受信上下文、账号归属校验和协议续转机制留待设计阶段论证。
