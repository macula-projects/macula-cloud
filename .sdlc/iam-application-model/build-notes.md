## 实现结构

- 三表应用聚合与来源用户绑定表使用中立命名；旧sys_user_identity_binding保持。V27自包含冻结转换，保留ID、原凭据编码、标识/有效期、审计、自增边界及历史非秘密快照。DDL前拒绝脏数据，暂存逐值校验、原子RENAME、发布复核；已有中间对象禁止自动覆盖，错误不含原始数据。
- 公共ApplicationProtocolDefinition与注册表按策略分派；v2组合OAuth设置，不改变v1类型或V18/V19。当前产品只注册OIDC/OAuth2.1。空草稿无协议，旧保留槽不可执行，资源身份没有业务grant。
- System按主行锁编排公共策略、协议/凭据及来源；HTTP兼容集中在WireAdapter。完整ETag基于DB落值，失配409；来源保存与删除使用共同来源锁，初始化幂等保留原凭据及人工配置。
- IAM的IamApplicationService以同一RR快照读取聚合；锁定读必须加入调用者可写事务。LoginApplicationResolver隔离受控请求解析；OAuth适配器校验参数唯一性、授权端点、响应类型、Scope/grant和精确回调。托管、浏览器、端内及绑定服务使用中立快照，账号服务按内部应用ID加载目录。
- OAuth2ClientRegistration是无ORM基类的协议投影，专属适配器读取受保护凭据。RegisteredClient.id/client_id保持原公开标识；资源身份同样规范化且保留内部内省哨兵。旧物理实体/Mapper与公共Client服务已移除，未生成package-info.java。
- 配置缓存两端使用v7；授权/Session类型、字段、UID、白名单和缓存键保持。显式来源FOR UPDATE与Crypto映射保持。
- 管理端通用注册表只调度，OAuth默认值及归一化进入专用策略；单选协议、创建后固定模式、EMAIL/SMS及来源选择的交互保持。
- IAM README及架构类图按当前职责说明模型与请求链，升级文档说明V27协调升级及失败恢复。
